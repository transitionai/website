# Transition website

The public marketing site and research notes for Transition, hosted at https://transitioned.dev on Cloudflare Pages. Next.js App Router, React, TypeScript, Tailwind CSS, and Fumadocs MDX. Static export writes to `out/`.

The dependency versions, pnpm workspace overrides/patch, and locally hosted fonts are adapted from the Loxa website. Loxa itself is unchanged. See font licenses under `app/fonts/` and `BRAND.md` for Transition's identity and claim boundaries.

## Run

Use Node 22 (`>=22.13 <23`) and pnpm 11.11.0:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Run from this `website/` directory. `postinstall` generates Fumadocs collections. `/` is the marketing page; `/approach` and `/approach/design-questions` are genuine Fumadocs research notes, not documentation for a shipped product.

## Check

```sh
pnpm check
```

This runs ESLint, TypeScript, and the static production build. Type checking requires generated MDX collections (`pnpm exec fumadocs-mdx` if not already generated by installation). No product integration, security, or runtime backend tests are implied.

Before release, preview the export with a local static server and review desktop/mobile layout, keyboard navigation, focus visibility, long text, the architecture diagram, every internal link, external profile links, favicon, and the mailto action. Check that the research status and architecture caveat remain visible.

## Website functionality

- Light/dark theme toggle with system default and persisted choice, including research pages and dialogs.
- Responsive navigation, Escape-to-close mobile menu, visible focus, reduced-motion and forced-color support.
- Local static research search with Cmd/Ctrl+K via Fumadocs; no external search service.
- Copy Markdown and View Markdown on each research note, backed by static text routes.
- `/llms.txt` index and `/llms-full.txt` research export. These contain public notes only.

Loxa's product install commands and hardware/platform features are intentionally not represented as Transition functionality.

## Automatic Markdown route checks

`pnpm build` runs `postbuild` automatically. The check inspects every exported research-page Markdown link, verifies its content and title, and starts a Next preview in an isolated temporary project copy to verify the same URLs return HTTP 200 with the correct text content. Unknown notes must return 404. The temporary process and project directory are cleaned up, and failures stop the build. This requires local loopback ports in the build environment; it needs no external service.

Run `pnpm check:markdown` to repeat this validation against an existing export. Run builds through `pnpm build` so the lifecycle hook runs; invoking `next build` directly bypasses it.
